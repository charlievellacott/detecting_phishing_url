# What I did
I build a classification model after visiting Netcraft's career day - I was insipired by the work they did. I began with a dataset from Kaggle, cleaned it, split it into training and testing data then looked for patterns/correlations in the format/lengths of different parts of the URL. I used urllib to parse the URL and split it into the different parts; before engineering some basic features. I extended the features by defining, cross-validating and training an n-grams model. I then saved the dataframes (basic features, URLs and labels), matrices (sparce numpy matrices for the n-gram weights), the vectorizer and the n-gram matrix columns. I reduced the dimensionality of the sparce matrices using single vector decomposition – this was to protect against the curse of dimensionality and produce a single rich feature set. I then dropped unnecessary columns and prepared the dataset for training by fitting and transforming a standard scaler to the input dataframe, before bundling the training dataframe and matrix together (via np.hstack). I fed this into the MLPClassifier with hidden layers of size 128 and 64; which after 32 iterations finished training. The MLP model used the ReLU (rectified linear unit) activation function, to reduce computational load, and the optimisation algorithm Adam to improve learning speed and accuracy. 
This was the final model that I produced.

# Performance
The model proved to be highly accurate with 97.2% of out-of-sample URLs being correctly classified. When we look at the confusion matrix, we can see that the false positive rate is 3%, the false negative rate is 2.6% with a roughly even class split (48% legit / 52% phishing). The most important of these metrics is the percentage of false negatives. A false negative is a phishing link that was undetected and would likely lead to security breaches. So, this low value is comforting to the success of this model; however, if deployed in a real scenario I would change the model such that the false negative rate is dropped and the false positive rate is raised, just to protect the client further.

# The validity of the model’s performance
I trust the metrics produced to a high degree on the dataset used. This is because of the large number of training samples, the near equal split between phishing and legit URLs and the early stopping used in the MLP model (reducing the risk of overfitting). However, the key limitation is the dataset itself: new phishing techniques may arise thus the model may have to be updated frequently to keep up; the labelling could be noisy or even incorrect for some URLs.
